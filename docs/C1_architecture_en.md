# Architecture

This document explains MemoquasarEterna's overall structure, memory schema, layer collaboration, and the role of adapters / connectors. For implementation details, see the Layer READMEs, `docs/C2_connector-contract_en.md`, `docs/C3_adapter-openclaw_en.md`, and `docs/C4_adapter-hermes_en.md`.

## Overall Structure

```text
{code_dir}/
  Core/
  Adapters/
  Installation/
  Maintenance/
  docs/
  OverallConfig-template.json
  README.md
```

| Directory | Responsibility |
| --- | --- |
| `Core/` | Memory engine: write, preserve, decay, read, landmark judge |
| `Adapters/` | External harness integration layer, e.g. OpenClaw, Hermes |
| `Installation/` | First install, config bootstrap, backfill, uninstall / refresh |
| `Maintenance/` | Rerun, backfill repair, failure recovery, manual ops scripts |
| `docs/` | User and maintainer documentation |

Core principle: `Core/` does not directly understand external platforms; `Adapters/` does not rewrite the main responsibilities of the memory engine.

## Why This Layering Exists

| Goal | Explanation |
| --- | --- |
| Separate core from platforms | Session reading, LLM calls, plugin installation, and other platform differences belong to adapters |
| Separate initialization from maintenance | First setup lives in `Installation/`; post-install repair and rerun live in `Maintenance/` |
| Keep repository structure extensible | New harnesses or layer features have stable ownership |

## Core Internal Structure

```text
Core/
  shared_funcs.py
  harness_connector.py
  Layer0_Extract/
  Layer1_Write/
  Layer2_Preserve/
  Layer3_Decay/
  Layer4_Read/
  LayerX_LandmarkJudge/
```

| Module | Responsibility |
| --- | --- |
| `shared_funcs.py` | Shared config loading, JSON read/write, standard output helpers |
| `harness_connector.py` | Loads `Adapters/{harness}/CONNECTOR.py` and routes MW / PA capabilities |
| `Layer0_Extract` | Harness raw input -> L2 / L1 init / staging |
| `Layer1_Write` | L2 -> chunk -> Map/Reduce -> L1 -> L0 / embedding / statistics |
| `Layer2_Preserve` | Archive / restore active surface memory |
| `Layer3_Decay` | Trim L2, shallow aggregation, deep aggregation, cleanup |
| `Layer4_Read` | Vague recall / exact recall |
| `LayerX_LandmarkJudge` | Long-term statistical analysis and landmark judgment based on records |

## Memory Schema: L2 / L1 / L0

| Schema | Main Role | Typical Consumers |
| --- | --- | --- |
| L2 | Daily raw transcript; highest fidelity and highest context cost | Layer1 map, Layer4 exact recall, evidence review |
| L1 | Daily structured summary suitable for humans and LLMs | Layer4 vague recall, Layer3 decay, statistics |
| L0 | Lightweight retrieval index | Layer4 query recall, embeddings, keyword search |

Short version:

- L2 answers “what exactly was said”.
- L1 answers “what happened that day”.
- L0 answers “is this day worth retrieving”.

### L2

Path:

```text
{store_dir}/memory/{agentId}/surface/YYYY-MM/YYYY-MM-DD_l2.json
```

Core shape:

```json
{
  "schema_version": "3.2",
  "date": "YYYY-MM-DD",
  "agent_id": "<agentId>",
  "status": "...",
  "conversation_excerpts": [
    {
      "role": "user|assistant",
      "time": "HH:MM",
      "content": "...",
      "message_type": "text",
      "turn_index": 0
    }
  ]
}
```

Notes: L2 is normalized by Layer0. `conversation_excerpts` is Layer1 chunk-planning input. `turn_index` anchors L1 `source_turns` / `emotional_peaks[].turn`.

### L1

Path:

```text
{store_dir}/memory/{agentId}/surface/YYYY-MM/YYYY-MM-DD_l1.json
```

Core shape:

```json
{
  "success": true,
  "schema_version": "3.1",
  "date": "YYYY-MM-DD",
  "agent_id": "<agentId>",
  "status": {...},
  "generated_at": "YYYY-MM-DDTHH:MM:SSZ",
  "stats": {...},
  "summary": "...",
  "tags": ["..."],
  "day_mood": "...",
  "topics": [{"name": "...", "detail": "..."}],
  "decisions": ["..."],
  "todos": ["..."],
  "key_items": [{"type": "milestone|bug_fix|config_change|decision|incident|question", "desc": "..."}],
  "emotional_peaks": [{"turn": 0, "emotion": "...", "intensity": 3, "context": "..."}],
  "_compress_hints": [0]
}
```

Notes: L1 is generated by Layer1 Map / Reduce, then Stage5 writes it back to the official surface file. `topics`, `decisions`, `todos`, and `key_items` are the main material for daily reading and vague recall. Reduce-generated `source_turns` ultimately become `_compress_hints`.

### L0

Paths:

```text
{store_dir}/memory/{agentId}/surface/l0_index.json
{store_dir}/memory/{agentId}/surface/l0_embeddings.json
```

`l0_index.json`:

```json
{
  "schema_version": "3.1",
  "agent_id": "<agentId>",
  "updated_at": "YYYY-MM-DDTHH:MM:SSZ",
  "entries": [
    {
      "date": "YYYY-MM-DD",
      "summary": "...",
      "tags": ["..."],
      "mood": "...",
      "depth": "surface",
      "access_count": 0
    }
  ]
}
```

`l0_embeddings.json`:

```json
{
  "schema_version": "3.1",
  "agent_id": "<agentId>",
  "model": "<embedding_model>",
  "updated_at": "YYYY-MM-DDTHH:MM:SSZ",
  "entries": {
    "YYYY-MM-DD::surface": {
      "depth": "surface",
      "embedding": [0.0],
      "text_used": "...",
      "generated_at": "YYYY-MM-DDTHH:MM:SSZ",
      "date": "YYYY-MM-DD"
    }
  }
}
```

Notes: surface L0 is extracted by Stage6 from official L1 fields (`date`, `summary`, `tags`, `day_mood`). Stage7 builds embeddings from L0. The unique surface key is `date + depth`; rerunning the same day overwrites the entry while preserving `access_count`.

## Main Pipelines

Daily write:

```text
harness raw data -> Layer0 Extract -> L2 -> Layer1 Map/Reduce -> L1 -> Stage6/7 -> L0 / embeddings
```

Long-term organization:

```text
surface L2/L1/L0 -> Layer2 Preserve -> archive backup -> Layer3 Decay -> trim L2 / shallow L1 / deep L1
```

Reading:

```text
query -> Layer4 -> L0 candidate dates -> L1 structured context -> L2 exact evidence when needed
```

Landmark:

```text
Layer1 Stage8 statistics -> LayerX_LandmarkJudge -> Layer3 decision making
```

## Connector and Adapter

`Core/` loads:

```text
Adapters/{harness}/CONNECTOR.py
```

through `Core/harness_connector.py`.

The connector contract lets core care only about capability names, not adapter internals. Current fixed interfaces include:

```text
ensure_config
memory_worker.call_llm / clean_runtime / prerequisites / install / uninstall
production_agent.extract / preserve / decay / prerequisites / install / uninstall
```

Current adapter status:

| Adapter | Status | Main Capabilities |
| --- | --- | --- |
| OpenClaw | production / default | Layer0 extract, MW call_llm, runtime cleanup, Layer4 plugin, Sessions_Watch preserve / decay |
| Hermes | experimental | PA Layer0 extract, Layer4 recall skill; no MW / preserve / decay |

## One-sentence Summary

MemoquasarEterna uses `Core/` as the memory engine, `Adapters/` as the external integration layer, and `Installation/` / `Maintenance/` for operations. Layer0-4 plus LayerX divide the full memory lifecycle.
